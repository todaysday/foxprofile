## Existing routes

The mounted REST routers have 36 operations on 30 paths. The proposed `/api/v1/ext` endpoints in [api-contract.md](api-contract.md) do not exist at baseline.

Exact current operations are `GET /api/v1/profiles`, `POST /api/v1/profiles`, `GET|PATCH|DELETE /api/v1/profiles/{name}`, `GET /api/v1/profiles/{name}/data-dir`, `POST /api/v1/profiles/{name}/export`, `POST /api/v1/profiles/import`, `GET|POST /api/v1/profiles/{name}/cookies`, `GET /api/v1/profiles/{name}/fingerprint`, `DELETE /api/v1/profiles/{name}/fingerprint`, `GET /api/v1/profiles/{name}/ip-check`; `GET /api/v1/browser`, `GET /api/v1/browser/{name}/status`, `POST /api/v1/browser/{name}/launch`, `POST /api/v1/browser/{name}/stop`; `POST /api/v1/browser/{name}/page/navigate`, `/back`, `/click`, `/type`, `/press`, `/click-at`, `/keyboard`, `/wait`, `/evaluate`, `POST /api/v1/browser/{name}/page/tabs`, `POST /api/v1/browser/{name}/page/tabs/{index}/select`, `DELETE /api/v1/browser/{name}/page/tabs/{index}`, and `GET /api/v1/browser/{name}/page/snapshot`, `/text`, `/screenshot`, `/tabs`; `POST /api/v1/proxy/check`, `POST /api/v1/proxy/geo-check`; `GET /api/v1/mcp/setup`.

The checkout contains one active change package with seven capability deltas; no pre-existing `openspec/specs/` living-spec tree was present at the audited source commit.

| Router | Operations and baseline classification |
| --- | --- |
| `profiles.py` (13) | `GET /profiles`, `GET /profiles/{name}`, `GET /profiles/{name}/data-dir`, `GET /profiles/{name}/fingerprint` are global/profile reads. Create, update, delete, fingerprint reset, and import mutate state. Profile export accepts a server path and writes a server file. Cookie export/import launch a stopped-profile browser helper and require the launcher's local exclusive lock. `GET /profiles/{name}/ip-check` performs an outbound diagnostic using stored profile settings. |
| `browser.py` (4) | List/status read global runtime state; launch and stop affect the selected browser. Launch may return HTTP 202 on `wait=false` or wait timeout while the run continues. |
| `page.py` (16) | Snapshot, text, screenshot, tabs, and wait observe the selected run. Navigate, back, click, type, press, click-at, keyboard, evaluate, tab create/select/close control it. The route resolves a profile name then calls launcher control; evaluate executes page JavaScript. |
| `proxy.py` (2) | Proxy check and geo-check make outbound diagnostic requests from submitted settings. |
| `mcp_setup.py` (1) | Protected shared-token configuration read. |

All five routers use `Depends(require_token)`. If no token is configured, this dependency does not identify a principal; `LocalOnlyGuard` instead checks Host/Origin. `/`, the allowlisted font route, health, info, OpenAPI/docs, and Starlette's `/mcp` transport are separate public or transport surfaces. `/mcp` uses the shared service token. The stdio MCP client also calls REST with that service credential. There is no baseline personal login, profile authorization, or WebSocket/noVNC route.

## Direct service, launch, and serialization seams

| Surface | Baseline source and behavior | Compatibility point |
| --- | --- | --- |
| Composition | `src/core/container.py:Container` owns one profile manager, browser launcher, proxy service, and event bus. `src/main.py` shares it between Flet and API. `src/interfaces/protocols.py` exposes actor-free profile and launcher methods. | Put policy at a shared facade used by both REST and direct callers; route decorators alone miss Flet. |
| Direct Flet catalog/runtime | `src/ui/app.py`, `handlers.py`, `actions/profile.py`, and `actions/browser.py` read the full profile dictionary and call manager/launcher directly. `actions/bulk.py` loops over single start/stop/delete calls. | Guard direct reads and effects; batch launch has no all-target preflight or atomic reservation. |
| Flet transfer/cookies | `actions/transfer.py` uses native file pickers and manager import/export. `actions/cookies.py` invokes cookie helpers under `exclusive(name)` and does fingerprint operations. | Personal server-file paths and helper launches need explicit policy and staging while preserving stopped-profile semantics. |
| Web panel | `src/web/index.html` stores the shared token in localStorage. Bulk launch fans out single requests. `openViewer`, `updateScreen`, `act`, and the `v-screen` handler poll screenshots every 2 seconds and send REST input. | Add personal session handling and a same-screen manual mode that suspends and restores this viewer's polling/input. |
| Main browser launch | `src/services/browser/launcher.py:BrowserLauncher.start_thread` uses process-local, profile-name keyed maps and locks. `process.py:spawn_browser` starts the runner with a copied service environment and merged stdout/stderr. Runner emits `CONTROL:<port>:<token>` before `BROWSER_STARTED`; launcher redacts the CONTROL line from logs. | Preserve readiness and result semantics while adding durable profile/run identity, shared admission, and isolated process context. In-memory running count is not cross-process capacity authority. |
| Other browser launch | `src/services/browser/cookies.py` starts `cookie_tool.py` as a separate browser process with `headless=True`; it is not a manual-display runtime. `chrome_engine/runner.py` treats virtual mode as headless. | Count helper launches; do not claim these or Chrome can attach to the Camoufox virtual display. |
| Local catalog serializer | At audited commit `530b993`, `src/models/profile.py:Profile.to_dict` and `src/services/profile/manager.py` load/save a name-keyed JSON catalog; the loader selects known fields and the model has no stable ID. The slice-1 checkpoint now includes separate slice-2 work adding a local `profile_id`. | Keep a local stable ID in the catalog while continuing to ignore unrelated/unknown fields. Manager locks and whole-file writes are per-process only. |
| Portable serializer | At audited commit `530b993`, `src/services/profile/transfer.py` exports `profile.json` through `Profile.to_dict`, optionally with `data/`; import rebuilds known fields after ZIP path checks. Local catalog and portable export share a representation there. The current model now exposes `to_portable_dict()` without `profile_id`; transfer integration remains slice-2 work. | Keep local identity out of portable archives; preserve path-staging and overwrite authorization outside caller-supplied server paths. |
| Browser data | `fingerprint.py`, `session.py`, runner, and Chrome persona code persist fingerprint, locale, tabs, cookies, and engine data under profile directories. | Preserve existing browser identity and portable transfer semantics during local ID/migration changes. |

Deployment assets at baseline are `deploy/foxprofile.service` and `deploy/nginx-foxprofile.conf`. The systemd unit uses a dedicated account, `PrivateTmp=true`, and filesystem restrictions. Nginx has no WebSocket upgrade forwarding. No noVNC client, x11vnc package, private VNC gateway, or per-profile process/filesystem confinement is present. CI is `.github/workflows/ci.yml`; manual live-browser scripts are under `tests/e2e/`.

## Evidence and limits

- A saved source inventory found 36 REST operations and hashed 160 tracked application, test, deployment, packaging, and CI files. Full route and command logs are preserved in the task workspace under `/workspace/work/tl010-baseline/`; the classification above is the reviewable repository summary.
- Audited checkout baseline: `pytest -q -m 'not browser'` produced **458 passed, 24 deselected**, with one Starlette/httpx deprecation warning, after adding `tzdata` to the disposable test environment. Before that environment-only fix, four timezone alias cases failed because the minimal Linux image lacked timezone data. No source or assertion changed. Ruff check passed and format check found 135 files formatted.
- At the initial slice-1 checkpoint, `pytest -q -m 'not browser'` produced **525 passed, 24 deselected**, with the same Starlette/httpx deprecation warning; that run included the 67 pure contract tests and preceded the compatibility harness. The focused compatibility command covered `test_ext_contracts.py`, `test_ext_compatibility.py`, `test_api_auth.py`, `test_transfer.py`, `test_launcher.py`, and `test_process.py`: an initial run produced **125 passed**, one warning. A later repeat after concurrent source changes produced **124 passed, 1 failed**; `/workspace/work/ind014-compatibility.log` records the failure. To verify standalone compatibility, the exact `f7ae12b0d15ff9e53ba35e5038d5769d0d212937` git archive was extracted into `/workspace/work/foundation-snapshot` and overlaid with only the five foundation modules and two foundation tests; those tests produced **71 passed**, one deprecation warning. The output is `/workspace/work/foundation-snapshot-tests.log`.
- Extension contracts cover immutable principal/profile/run DTOs, public manual-session shape, private runtime descriptors, stable errors, role/service separation, assignment lookup, and pure capacity policy. The composition factory binds an application assignment lookup but does not authenticate credentials or create application services. Compatibility tests exercise the legacy service-token dependency and launch route/service call shape, the current local and portable profile serializers, and the actual launcher protocol parser against the runner's CONTROL-before-ready source order.
- Ruff check and format check pass for the seven slice-1 foundation/test files. A `python -S` import of the public `foxprofile_ext` package verified it does not import FastAPI, Flet, SQLite, browser packages, or `src`.
- The 24 deselected tests require real browser fixtures. No browser, live service, external target, noVNC/helper, WebSocket, host isolation, ARM64, or x86-64 live acceptance check ran. Baseline test results establish upstream test health only; they do not verify the proposed feature.
