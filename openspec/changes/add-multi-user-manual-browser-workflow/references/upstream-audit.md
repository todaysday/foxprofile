## Configuration and deployment details

- [`src/core/config.py`](https://github.com/chienbm98/foxprofile/blob/530b993ff3a7d211aaa0904fba0817b77c75d4c9/src/core/config.py) preserves the string `virtual` in its headless parser. Other truthy values become `True`.
- [`src/server.py`](https://github.com/chienbm98/foxprofile/blob/530b993ff3a7d211aaa0904fba0817b77c75d4c9/src/server.py) loads `.env` before imports, defaults `FOXPROFILE_HEADLESS` to `true` with `setdefault`, and lets `--headed` override it. A virtual-mode deployment must set the environment before imports and must not use `--headed`.
- [`deploy/foxprofile.service`](https://github.com/chienbm98/foxprofile/blob/530b993ff3a7d211aaa0904fba0817b77c75d4c9/deploy/foxprofile.service) uses `PrivateTmp=true`, restrictive filesystem permissions and a dedicated service user. Start Xvfb/VNC helpers within the same service namespace or they may not see the X socket. Do not remove hardening globally as a convenience workaround.
- [`deploy/nginx-foxprofile.conf`](https://github.com/chienbm98/foxprofile/blob/530b993ff3a7d211aaa0904fba0817b77c75d4c9/deploy/nginx-foxprofile.conf) forwards to loopback and is currently oriented to ordinary HTTP/SSE; the noVNC WebSocket route needs upgrade forwarding and suitable connection timeouts.
- [`pyproject.toml`](https://github.com/chienbm98/foxprofile/blob/530b993ff3a7d211aaa0904fba0817b77c75d4c9/pyproject.toml) targets Python 3.10+; the project has existing interfaces, dataclasses and Pydantic request/response DTOs. Reuse those patterns.

## Suggested minimal persistence decision

This paragraph is a design recommendation, not a description of upstream.

Keep the existing JSON profile catalog and browser-data directories. Add one immutable local profile_id to the model and local catalog serialization; exclude it from portable ZIP metadata and ignore identities supplied by imports. Use a sidecar SQLite database through small DAO boundaries for users, sessions, assignments, settings and runtime reservations. A finite catalog adapter coordinates a shared file lock, refreshed snapshots and operation intent/recovery for interrupted create/import/rename/delete steps. Surface existing silent catalog-save failures and prevent name reuse while residual deleted-profile data remains. This additive design minimizes upstream changes without relying on profile names as permanent identity. Browser processes remain outside database transactions. Multiple API workers must agree on a runtime owner or use a registry-aware process controller; a SQLite counter alone does not make process-local launchers share live handles.
