## Gaps that require new implementation

The inspected checkout has no personal user/session/assignment store, immutable profile ID, cross-process capacity reservation, durable browser-run identity, installation-wide manual lease, authenticated VNC WebSocket gateway, private VNC helper channel, or per-profile filesystem/process confinement. The current runtime runs browser subprocesses under the service account; it does not sanitize inherited environment variables. Existing API token checks, URL filtering, per-profile in-process locks, one display per process, and `control.serve` loopback binding do not establish these missing boundaries. The proposal therefore uses a small `foxprofile_ext` package with explicit policy, DAO, runtime, and UI adapters; it does not replace upstream modules or create a general plugin framework.

This checkout has no vendored or pinned noVNC client or x11vnc source/package. The x11vnc manual linked from `design.md` is documentation, not inspected implementation source; no third-party revision, symbol set, or license is represented here as already reused. The existing implementation task 8.3 requires pinning and validating the actual client/helper packages and their licenses before packaging. No SQL DAO is present either; the design uses Python's standard-library SQLite through narrowly scoped DAOs rather than claiming an existing DAO can be reused.

## Verification boundary

This is source and test inspection evidence only. The named existing tests were inspected but were not run for this documentation change. They establish current upstream contracts, not implementation or live acceptance of the proposed feature. No noVNC connection, backend-channel isolation, 60-second cleanup behavior, geometry measurement, or ARM64/x86-64 result has been executed; the acceptance plan leaves those checks `NOT RUN`.
